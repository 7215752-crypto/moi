# План развития портала MOI Group

Цель: единое рабочее пространство менеджера ресторана — зарплата, планирование выручки, товарная аналитика. Порядок этапов соответствует карточкам на дашборде: сначала добиваем модуль «Сотрудники» (ЗП), затем «Планирование», затем «Аналитика».

- [ ] Удалить папки `backup-*` и файлы `*.backup` (история переедет в git).

## Этап 1 — завершить модуль расчёта ЗП

Сейчас портал показывает готовый расчёт. Надо, чтобы расчёт собирался и подтверждался внутри портала:

1. **Вернуть импорт в UI** — страница «Импорт данных» для owner/accountant: график смен (компонент `google-schedule-card.tsx` уже есть, выпал при редизайне), ставки из Google-таблицы с записью в базу.
2. **Импорт из iiko API** — фактические часы (посещаемость) и мотивация, вместо ручной загрузки.
3. **Формы ввода** — сервисный сбор и инвентаризация по ресторану за период.
4. **Корректировки** — премии/депремирование с комментарием и автором (сейчас `fine`/`tg_bonus` приходят извне).
5. **Жизненный цикл расчёта** — статусы периода/версии (черновик → на проверке → утверждён → выплачен), пересчёт новой версией, сравнение версий.
6. **Шифт-лидерские смены** — карточки подтверждения (`leader_shifts.status`: pending → confirmed), начисление `leader_kpi` из подтверждённых смен.
7. Починить выбор версии на дашборде и странице периода (версия должна браться по ресторану, см. PROJECT-OVERVIEW.md, п. 4 наблюдений).

Результат этапа: бухгалтер собирает период целиком в портале, менеджер видит свой ресторан, сотрудники получают понятные листки.

## Этап 2 — «Планирование» (карточка 01)

- План выручки по ресторанам на месяц (ввод в портале).
- Факт из iiko (ежедневная выручка) и % выполнения.
- Прогноз до конца месяца (по темпу текущего месяца и сезонности дней недели).
- Связка с ЗП: ФОТ как % от выручки — ключевая метрика менеджера.
